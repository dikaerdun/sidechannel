# 真实 ML-KEM NTT：从 256 个系数到 128 个二系数小块

本模型逐步实现 [FIPS 203 第 4.3 节、算法 9–12](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.203.pdf)。它使用标准参数 q = 3329、n = 256、ζ = 17；每个数字均为普通模整数，不包含 Montgomery 编码。

## 给学员的讲法

把一个有 256 个系数的多项式想成一张很长的计算单。NTT 通过可逆的拆分，把它改写为 128 张各含两个数字的小计算单。乘法随后可以在每张小单内部独立进行，再用逆 NTT 合并。小单里的数字是原系数的线性组合，并非把原来的数组简单切段。

为何留两个数字？ML-KEM 计算的环满足 X²⁵⁶ = −1。模 3329 没有 512 次本原单位根，因此 X²⁵⁶ + 1 在这个域上只能分解到 128 个二次因子，不能拆成 256 个一次因子。

| 层 | 蝶形左右索引间距 len | 层结束后的块数 | 每块系数数 |
|---:|---:|---:|---:|
| 1 | 128 | 2 | 128 |
| 2 | 64 | 4 | 64 |
| 3 | 32 | 8 | 32 |
| 4 | 16 | 16 | 16 |
| 5 | 8 | 32 | 8 |
| 6 | 4 | 64 | 4 |
| 7 | 2 | 128 | 2 |

每层 128 次蝶形，共 896 次。每次读取 u、v，先算 t = zeta × v，再写回 (u+t, u−t)，全部模 3329。第一个旋转因子是 17⁶⁴ mod 3329 = 1729；如果 u=1、v=3，则 t=1858，左右结果为 1859、1472。

末端的第 b 个小块对应 X² − γᵦ，其中 γᵦ = 17^(2 BitRev₇(b)+1) mod 3329。两个小块 (a₀+a₁X)、(b₀+b₁X) 相乘时，用 X²=γᵦ 折回：

- 常数项：c₀ = a₀b₀ + γᵦa₁b₁。
- 一次项：c₁ = a₀b₁ + a₁b₀。

例如第 0 块 γ₀=17；(1+2X)(3+4X) 在这一块内变成 139+10X。

逆 NTT 由短间距逐层恢复长间距，最后每项乘 3303，也就是 128⁻¹ mod 3329。正逆变换会精确恢复所有系数。

## 与四点入门实验的边界

四点循环 NTT 的教学模型可在模 17、X⁴−1 下使用四个点值，最后做四个独立标量乘法。真实 ML-KEM 在模 3329、X²⁵⁶+1 下使用 128 个二系数块，最后做块内乘法。两者都帮助理解“改变表示，让乘法变简单”，但根、折回符号和末端乘法不可混用。

## 前端接口

```js
const trace = RealNTT.forward(coefficients); // 必须恰好 256 个安全整数
trace.input;  // 规范化到 0..3328 的输入副本
trace.output; // 256 个变换输出，按 128 个二系数块排列
trace.stages; // 7 个层末快照，不包含输入快照
trace.logs;   // 896 个蝶形操作记录
RealNTT.inverse(trace.output); // 256 个恢复后的系数
RealNTT.gamma(0); // 17
RealNTT.baseMultiply([1, 2], [3, 4], 17); // [139, 10]
RealNTT.multiply(a, b);   // 系数输入 -> NTT -> 块乘 -> INTT
RealNTT.schoolbook(a, b); // 系数输入 -> 学校式负循环乘法
```

日志中 stage 从 1 开始；i、j 为左右系数下标，j=i+len；u、v 是读入值，t 为模乘结果，left、right 为写回值。twiddleIndex 对应标准算法 9 的变量 i；start 是本组起点。重放时，从 trace.input 拷贝数组，依次写回两个位置即可，无须为每个蝶形存储整幅快照。

## 验证与用途

执行 `node tests/verify-real-ntt.cjs`。独立参考实现先用 BigInt 计算 511 项普通卷积，再执行 X²⁵⁶=−1 的折回；另用独立 CRT 余式计算核对 NTT 输出次序。

本次通过 280 次正逆往返（含全部 256 个基向量）、24 次 CRT 对照、26 次乘法对照、24 条完整蝶形轨迹重放，共 65165 项断言。边界例子 X²⁵⁵×X=−1、X²⁵⁵×X²⁵⁵=−X²⁵⁴ 均通过。

模型适合课堂逐步展示；日志会主动暴露中间值，也没有提供恒时或侧信道防护，不应作为生产密钥处理代码。
