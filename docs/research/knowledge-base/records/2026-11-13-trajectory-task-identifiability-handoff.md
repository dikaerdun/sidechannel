# 轨迹编码 任务安全与可辨识性的验证交接

日期：2026-11-13。用户希望进一步扩大构思，由其他人验证。[本批提案](../brainstorms/2026-11-13-trajectory-codes-task-security-identifiability.md)列出六个开放问题，详细展开三项。它们深化既有方向，不增加 40 条 BOLD 种子的计数，也不升级实验状态。

轨迹编码方向给出两条布尔转移联合保留秘密差分的手工见证。该例只有联合信息，不是对一阶掩码的反例；固定秘密的相同状态转换也不会因此泄漏。验证者先定义有实际依据的观察族，再比较候选构造与已有有状态和 robust probing 防护。

任务安全方向给出有限域行空间见证：完整向量仍有歧义时，某些线性任务已经可计算。验证者须明确目标属于内部诊断还是协议安全，并比较同公开信息、同预算基线；不能把小候选集、私有标签准确率或信息论熵直接当作密码学破坏。

可辨识性方向给出状态空间相似变换的等价见证，并保留重要修正：纯坐标变化不是两个可被实验区分的物理机制。验证者须先划出等价类，再寻找有独立物理含义的锚点或真正分叉的干预预测。此项保留偏离现有离线波形主线的小规模理论诊断。

本轮完成历史去重、定位性原始来源阅读、文档与知识库入口更新。手工见证由主 Codex 提出，尚待独立核验；没有运行实验、仿真、训练，没有启动 Agent，也没有向他人发送任务。待验证者回传后，再追加反例、认识变化和保留或放弃理由。
