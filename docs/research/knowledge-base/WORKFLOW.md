# 研究与知识入库流程

更新日期：2026-11-07。本文是研究协议建议，不是实验结果。

## 角色与独立性

主 Codex 负责实现映射、实验执行与集成；理论 GPT Agent 负责独立构思、跨学科模型和竞争解释；核验 GPT Agent 负责协议检查和关键结果复算，不编写被其核验的主实验实现。

首次构思仅共享中性事实包：任务、原始来源、数据说明、适用规则、已核实正负结果及未知项。主 Agent 的候选答案在双方提交初稿后再交换。工具支持时采用新上下文；无法隔离时记录限制。独立上下文不保证不同模型偏差，不能用投票代替证据。

核验分两步：先从冻结协议和输入独立计算，再比较主程序结果及解释。允许随后检查实现；应记录核验者何时看到主结论。记录输入版本、输出、运行命令与实际核验范围。报告审阅不等于运行复算。

子代理只写各自获分配的输出目录；原始数据只读。提示词约定不是访问控制隔离，不宣称共享文件系统已经物理隔离。

## 一轮研究

1. 恢复项目状态，阅读历史正负结果，排除重复命名的旧方案。
2. 主 Codex 与理论 Agent 各提三个机制不同的种子，至少一个挑战现有前提，一个给出“原概念 → 变量 → 假设 → 预测”。
3. 先互相补强，再提出反例，最多选择三个候选；为一个不同于主线的合格方向保留小规模诊断。
4. 冻结模型卡与实验协议：变量、实现位置、基线、竞争解释、主要指标、数据划分、预算及否定条件。
5. 运行最小鉴别实验。区分代码错误、数据条件不足、检验能力不足和预测不成立；修改假设建立新版本。
6. 核验 Agent 独立复算关键结果；主 Agent 处理分歧。无法解决的分歧保持开放。
7. 形成“主张—证据—适用范围—反证—下一步”条目，更新索引，完成同步并核对远端。

## 证据标准

- 分开泄漏检出、预测改善、局部变量恢复、会话秘密恢复、长期私钥恢复和物理归因。
- 数据按完整执行以及声称的泛化维度划分；同一执行的窗口、同一签名内部尝试不跨集合混用。
- 窗口、特征、归一化和超参数只使用开发数据确定。最终测试真值只交独立评估，不进入候选生成和攻击评分。
- 记录全部探索变体。确认集一旦用于调整模型，就成为开发数据；后续确认需新的独立数据。
- 历史模型加入错误历史绑定，结构模型加入错配结构对照，并使用合理的同容量基线。对照改变的条件必须写清。
- 分类后验不能不处理先验就当似然；重叠窗口和共同噪声不能任意当作独立证据相乘。
- 推断收敛不代表推断正确。关键小问题用精确计算或独立实现检查。
- 负结果只约束已测试的版本和条件。运行报错不算否定机制。
- 模拟、教学和真实测量分别标记；引用作者结果不能写成我们已复现。

## 入库与发布

复用本目录与原有研究资料，不建立平行的重复索引。每批至少更新模型索引、实验记录和 NEXT_ACTION。实用的负结果、失败对照、环境约束和复算脚本同样入库。

公开仓库仅提交经过筛选的研究摘要、代码、配置、必要的小结果和来源链接。原始波形及大型模型保存可访问位置、来源、版本与校验值；不默认提交大文件。知识库不收录凭据、私人路径、个人通信、未授权材料或第三方论文全文。未知字段写“未知/未核查”，不能补猜。

保留本地完整工作日志；公开的 Agent 意见保留相关原文片段、角色、输入版本及运行状态，注明删节范围。不要将内部推理过程作为要求或证据。

更新前读取远端最新版本及规则。检查新增路径、来源与状态标签、相对链接、意外数据文件和差异。按仓库允许的方式提交；需要 PR 时使用 codex/ 前缀分支，保留具体链接。没有保护或审批要求的小型文档更新可在已有授权范围内直接同步，不能为了例行文档更新反复请求批准。遇并发更新先重读与合并，不强推覆盖。

报告区分本地完成、已提交、已推送和已合并。远端 SHA 与内容确认后才称“已同步”。网络或认证失败时保存本地成果，继续其他可执行工作，不假装后台同步。
