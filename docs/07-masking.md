# 第 7 章　掩码的数学保证与硬件现实

[目录](../README.md) · [上一章](06-advanced-analysis.md) · [下一章](08-timing-classical.md)

## 7.1 掩码试图改变什么

隐藏型防护主要降低可观测信号或增加对齐困难；掩码则改变中间值的表示，希望每个允许被观测的局部量与秘密独立。

对 w 位秘密 X，取均匀独立的 w 位 R，设：

$$X_0=R,\qquad X_1=X\oplus R.$$

对任意 x、a，都有 Pr(X_0=a|X=x)=2^−w，X_1 同理。因此单独知道任一完整份额，都不增加 X 的信息。

前提必须说完整：R 均匀且满足独立性要求；观察对象只有一个份额；生成、使用、刷新和传输过程没有把两个份额重新暴露。仅把寄存器数量翻倍不构成这个保证。

## 7.2 从一个比特推导二阶泄漏

令 X、R 为比特，无噪声泄漏为 A=R，B=X⊕R。无论 X 是 0 还是 1，A 与 B 的边缘均值都是 1/2。

但观察中心化乘积：

$$Z=(A-1/2)(B-1/2).$$

| X | R | A | B | Z |
|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | +1/4 |
| 0 | 1 | 1 | 1 | +1/4 |
| 1 | 0 | 0 | 1 | −1/4 |
| 1 | 1 | 1 | 0 | −1/4 |

单独看 A 或 B 不行，联合关系却完全区分 X。**掩码没有让秘密消失，而是把信息移到了多个份额之间的关系。**

若 A、B 含独立零均值噪声，乘积的条件期望仍保留这个信号，但方差会变大，估计更困难。若噪声相关，还会出现额外项，不能沿用简化结论。

## 7.3 推广到字节汉明重量

令 A=HW(R)，B=HW(X⊕R)。对固定 w 位 X，R 均匀独立，按位展开得到：

$$\mathbb E[(A-w/2)(B-w/2)\mid X]=\frac{w-2HW(X)}4.$$

推导：不同位之间的中心化项期望为零；同一位若 X_j=0，贡献 +1/4；若 X_j=1，贡献 −1/4；将 w 位相加。

对字节 w=8，期望为 2−HW(X)/2。于是原本为零的一阶相关，可以在两点中心化乘积上变成与 HW(X) 相关的量。

配套实验令 X 为 AES S 盒输出，生成两份 HW 泄漏。它展示一阶与二阶评分的区别，并用精确枚举验证上述等式。这个模型不是任何真实掩码芯片的完整泄漏模型。

## 7.4 一个比二阶攻击更直接的陷阱：份额之间的转换

假设同一个物理寄存器先装 R，再装 X⊕R。更新时的汉明距离为：

$$HD(R,X\oplus R)=HW(X).$$

两个份额各自均匀，**它们在同一节点上的连续转换却直接重新暴露了秘密的 HW**。此时不必分别测两个时间点再相乘。

这说明“份额的值独立”与“份额的转换独立”是不同保证。时间复用的算术器、共享总线和存储端口尤其需要分析旧状态、预充电、刷新与实际调度。

## 7.5 线性运算与非线性运算为何成本不同

对于线性映射 F，有 F(X_0⊕X_1)=F(X_0)⊕F(X_1)，可逐份额计算。但对于 AND：

$$xy=x_0y_0\oplus x_0y_1\oplus x_1y_0\oplus x_1y_1.$$

跨份额乘积出现了。直接把它们计算并异或起来，可能在某个节点、瞬态或转换中合并秘密。安全 gadget 要安排这些交叉项、随机掩蔽、寄存器边界与组合规则。

“一个乘法结果正确”只说明功能，不说明各内部观测安全。也不要把在理想无毛刺模型中成立的门级公式原样作为 FPGA RTL 的安全实现。

## 7.6 布尔掩码与算术掩码

布尔表示：X=X_0⊕X_1；算术表示：X=(X_0+X_1) mod q。前者适合比特逻辑，后者适合模加和乘公开常量。

比如 T 是模 q 线性变换，则 T(X)=T(X_0)+T(X_1) mod q。这解释了为什么 NTT 可以逐算术份额处理。但比较、压缩、舍入、位提取、哈希等并不都在线性算术域中，往往需要专门保护或安全转换。

因此 PQC 安全实现的难点可能位于 NTT 前后，而不是只在 NTT 蝶形内部。转换、采样、比较、Keccak、存储和状态选择必须一起分析。

## 7.7 高阶与探针模型应怎样理解

在某些理想探针模型中，d 阶安全要求任意至多 d 个允许观测的内部变量联合起来也不泄漏秘密。常见加法共享使用 d+1 个份额，但份额数本身并不保证门级组合、毛刺或转换安全。

真实模拟探头会观察许多节点的混合，不天然等于“一个探针读一个理想变量”。探针模型是证明抽象；需要说明如何映射到真实电路，并通过门级、布局后分析及实测寻找模型遗漏。

TI 与 DOM 是把硬件问题纳入掩码设计的重要路线。阅读时应关注正确性、局部依赖、输出共享分布、组合前提、随机数使用与流水线条件，而不能只比较面积数字。[TI 原论文](https://link.springer.com/chapter/10.1007/11935308_38)；[DOM 原论文](https://eprint.iacr.org/2016/486)

## 7.8 随机数受限时真正的研究问题

要区分算法随机量、掩码随机量和打乱调度随机量。它们的用途、安全定义和更新频率不同。

TRNG 的熵输入速率与安全伪随机扩展后的掩码消耗速率也不同。后者可以改善吞吐，但将信息论独立假设换成计算性假设，并引入生成器状态、隔离、复位、重播、域分离与物理泄漏问题。

“随机数少一点”只有在证明或严谨分析支持的范围内才是优化。盲目复用掩码可能制造跨周期关系，抵消原本的随机化。
