# 第 13 章　怎样判断“有泄漏”“能攻击”与“足够安全”

[目录](../README.md) · [上一章](12-secure-hardware.md) · [下一章](14-research-thinking.md)

## 13.1 Welch t 检验在问什么

对两组测量 A、B，逐时刻计算：

$$t=\frac{\bar L_A-\bar L_B}{\sqrt{s_A^2/n_A+s_B^2/n_B}}.$$

它衡量均值差相对于估计误差的大小。常见一阶 TVLA 流程以固定组与随机组比较，采用 |t|>4.5 的筛查约定，并要求独立重复。特定 DTR 对二阶还规定不同阈值，不能把一个数推广到所有方法和全部阶数。[TVLA DTR with AES](https://www.rambus.com/wp-content/uploads/2015/08/TVLA-DTR-with-AES.pdf)

不要将 4.5 解释成“系统泄漏概率”或“密钥恢复概率”。扫描许多采样点、组合与反复试验，会产生多重检验问题；单点阈值不是整个搜索过程的统一误报控制。

## 13.2 一阶检验可能漏掉什么

若 L|X=0 与 L|X=1 的均值相同，但方差不同，一阶均值检验可能没有明显差异；二阶特征能看见差别。第 7 章的两份额模型更进一步：单点边缘分布可以相同，而两点联合关系依赖秘密。

因此“未越阈”只能表述为：在某组输入、观测通道、预处理、统计阶数和数据预算下，未检测到相应差异。

配套实验故意构造同均值、不同方差的分布，让一阶与二阶结果不同。这是统计反例，不是对任何产品作出的测试。

## 13.3 越阈又可能是什么

固定输入与随机输入本来就不同，公开输入的处理可以产生分布差异。测试夹具、不同内存地址或采集顺序也能带来差异。

所以要先定位泄漏来源，再判断是否增加秘密相关信息。在敏感计算窗口找到可重复差异，是需要调查的证据；不是已经完成私钥恢复的证明。

## 13.4 攻击结果应该怎么报告

| 指标 | 含义 | 报告时要补充 |
|---|---|---|
| 真密钥排名 | 正确候选排在第几 | 从 0 或从 1 开始，是否含并列 |
| 猜测熵 GE | 多次试验中排名的平均值 | 试验次数与不同设备/数据条件 |
| 成功率 SR(N) | N 条观测下成功恢复的比例 | 成功定义与置信区间 |
| 最佳错误候选差距 | 正确与错误评分的分离程度 | 评分方法与窗口是否预先固定 |
| 目标数据量 | 需要多少目标观测 | 模板训练数据另计 |
| 总成本 | 时间、内存、设备、训练与测量 | 是否包含预处理和候选搜索 |

一个字节排第一不等于整把密钥恢复。把多个字节的局部分数组合成完整密钥，可能仍需额外搜索；不同字节的误差也不一定独立。

## 13.5 防止把分析者知识偷偷给了攻击者

已知真密钥可用于实验诊断、验证中间值、计算排名。若用它在目标测试集上挑选最优兴趣点、最优噪声种子或最佳窗口，然后声称“未知密钥自动攻击成功”，就混淆了角色。

正确做法是划分探索集、验证集和最终测试集，先固定方法，再报告结果。本仓库的合成实验中，注入时刻与模型由教程预设，属于教学知识；脚本会明确标注，不据此估计真实设备攻击难度。

## 13.6 阅读论文的十个问题

1. 攻击的是哪个算法版本与具体实现？
2. 所有输入、密钥、随机量与中间值中，哪些可知、哪些可控？
3. 测量通道、位置和带宽是什么？
4. 模型猜测的是数学值、编码值，还是状态转换？
5. 模板设备、训练标签从哪里来？
6. 单迹线是否隐藏了大量训练成本或一次操作中的大量样本？
7. 结果是检出差异、恢复临时量，还是恢复长期密钥？
8. 是否有多次独立试验、失败情况和参数敏感性？
9. 防护对比是否保持了同样的对手能力和数据预算？
10. 论文证明或实验没有覆盖的边界是什么？

## 13.7 一张可复用的研究记录卡

每研究一个实现，按以下字段记录即可：

| 字段 | 填写内容 |
|---|---|
| 对象 | 标准、参数、代码/RTL 提交、综合/编译配置 |
| 秘密 | 长期/临时、生命周期、复用次数 |
| 对手条件 | 已知输入、选择输入、模板能力、物理接触 |
| 泄漏链 | 敏感表达式 → 硬件表示 → 物理现象 → 测量特征 |
| 推断 | 候选空间、模型、统计量、联合约束 |
| 数据 | 探索/训练/验证/测试的划分与采集批次 |
| 结果 | 排名、成功率、数据量、时间、独立复现 |
| 防护 | 改变的机制、总成本、剩余边界 |

这张卡能迫使“这篇论文很厉害”变成“我知道它为什么成立，以及能否用于我的 IP”。
