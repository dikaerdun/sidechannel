# 第 8 章　时序与传统密码：建立跨算法的共同认识

[目录](../README.md) · [上一章](07-masking.md) · [下一章](09-ntt.md)

## 8.1 时序也是一个带噪声的观测量

把一次运行总时间写成：

$$T(x,k)=T_0+T_{secret}(x,k)+N.$$

秘密相关分支、循环次数、访存地址、约减次数及变时延指令，都可能进入 T_secret。远程测量还叠加网络与调度噪声，但不能因此默认秘密相关项不可估计。

Kocher 的早期研究展示了如何用运算时间对秘密指数的候选逐步推断；关键在于某个候选预测的局部耗时能否解释总时间变化。[Timing Attacks，CRYPTO 1996](https://paulkocher.com/doc/TimingAttacks.pdf)

## 8.2 三种经常混用的“恒定”

| 声明 | 真正含义 | 仍未保证的部分 |
|---|---|---|
| 分支路径固定 | 指令路径不依赖秘密 | 数据依赖指令耗时、地址、功耗 |
| 周期数固定 | 指定模型下总周期相同 | 每周期电流、电磁与存储活动 |
| 物理时间稳定 | 测量条件下总时间近似稳定 | 局部幅度与联合分布的秘密依赖 |

固定延迟乘法器可以抵御该乘法器的输入相关完成时间差，但其内部加法器、进位和寄存器仍可能有数据相关活动。

所以实现审查要从源码下沉到汇编、RTL、门级或真实芯片。源码没有显式 `if`，不代表机器指令、综合结果和外围控制逻辑不引入秘密依赖。

## 8.3 AES 与 SM4：共同点是局部非线性和轮密钥

AES 的 S 盒输出适合演示按字节猜测，硬件实际模型应考虑轮状态与写回 HD。SM4 同样有字节 S 盒，但轮函数组织和轮密钥使用方式不同，不能把 AES 脚本中的索引直接换名字。

SM4 某轮 S 盒输入由三个状态字与轮密钥异或形成；若相应状态可计算，可针对轮密钥字节提出预测。首轮或末轮之所以常被考虑，是因为与公开输入输出关系更直接。中间轮需要更多未知状态，猜测问题可能扩大。轮函数英文说明可参阅[SM4 草案](https://datatracker.ietf.org/doc/html/draft-ribose-cfrg-sm4-10)，该草案已经过期，不是正式标准的替代品。

这段是依据轮函数结构作出的分析，不声称对任意 SM4 硬件都能按字节恢复。保护 S 盒之外，也要检查密钥扩展、状态迁移和轮间共享资源。

## 8.4 RSA：从控制流到数据流

平方乘方法可能按指数位决定是否做乘法，造成操作序列差异。改成统一序列可以减少 SPA 线索；若条件选择、乘数、约减路径或寄存器旧值仍依赖秘密，其他方法仍可能使用这些信息。

指数盲化、消息盲化等让多次操作的中间值关系随机化，作用与单纯加延时不同。不过盲化随机量生成、取值范围和使用过程本身也进入安全边界。一个只保护模幂主体、却泄漏盲化因子的实现，不能获得预期保证。

## 8.5 ECC：临时量为什么通向长期密钥

对 ECDSA，在群阶 n 上有以下标准签名关系（背景见 [FIPS 186-5](https://csrc.nist.gov/pubs/fips/186-5/final)）：

$$s=k^{-1}(h+rd)\pmod n.$$

公开签名为 (r,s)，消息摘要为 h，长期私钥为 d，临时随机标量为 k。若完整 k 被恢复，且 r 可逆，则：

$$d=(sk-h)r^{-1}\pmod n.$$

这不是求解椭圆曲线离散对数，而是利用签名代数关系。部分 k 信息也可能形成约束，但能否恢复 d，取决于泄漏位数、位置、错误率和签名数量；不能一概说“泄漏一点就一定丢私钥”。

规则的点运算序列、坐标随机化和标量盲化分别影响不同观测面。必须说明它们打断的是哪条秘密—中间值—泄漏关系。

## 8.6 可以迁移到 PQC 的思维

| 传统密码经验 | 在 PQC 中对应的追问 |
|---|---|
| S 盒中间值支持局部猜测 | 一个系数、乘积、判定位能否形成小候选集合？ |
| 模幂中的重复操作支持横向分析 | 多项式系数和 NTT 蝶形能否在单次执行中提供重复观测？ |
| ECC 随机标量与长期私钥有关 | 签名临时多项式泄漏后，公开签名会暴露什么约束？ |
| 完成时间之外仍有功耗 | 固定周期 NTT 是否仍有秘密相关翻转？ |
| 盲化与掩码需保护全过程 | 采样、变换、比较、哈希和存储是否跨越保护边界？ |

学习多个算法的目的，是把“寻找局部可预测变量—确认物理可见性—累计统计证据—利用代数关系”的分析方法迁移过去。
